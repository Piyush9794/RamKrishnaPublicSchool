# FRONTEND — SCHOOL MANAGEMENT SYSTEM

Build the complete **School Management System frontend** as an independent React application.

```text
school-management-system/
├── frontend/
└── backend/          # Backend will be developed separately
```

**This phase must create ONLY `frontend/`. Do not create backend code inside it.**

## 1. Technology

Use:

```text
React + Vite
JavaScript
Tailwind CSS
Framer Motion
Lucide React
React Router DOM
Axios
Context API
React Hook Form
```

Use reusable components, clean architecture, responsive design, and no unnecessary dependencies.

## 8. Teacher Self-Attendance + Location

Teacher opens:

```text
/teacher/attendance
```

Display:

```text
Today's Attendance
Status: Not Marked
📍 Location Required
[ Mark My Attendance ]
```

On click, use:

```javascript
navigator.geolocation.getCurrentPosition()
```

Capture:

```text
latitude
longitude
accuracy
timestamp
```

### Current Rule

```text
ANY LOCATION → Attendance Allowed
             → Location Captured
             → Location Sent To Backend
```

Currently:

```text
NO GEOFENCING
NO SCHOOL-RADIUS VALIDATION
NO LOCATION-BASED REJECTION
```

API file:

```text
src/services/teacherAttendance.api.js
```

Request:

```json
{
  "status": "Present",
  "latitude": 26.8467,
  "longitude": 80.9462,
  "accuracy": 15,
  "locationTimestamp": "2026-10-02T08:30:00.000Z",
  "remarks": ""
}
```

Do **not** send teacher ID. Identify the teacher through authentication.

Location states:

```text
Detecting location...
Location detected ✓
Permission denied → ask user to enable location
Unavailable → ask user to check GPS/location
Timeout → allow retry
Unsupported → show browser support error
```

Never silently mark attendance if location permission fails.

## 30. Final Rules

1. Create **only `frontend/`** in this phase.
2. Keep `backend/` completely separate.
3. Exactly **3 login roles: Admin, Teacher, Parent**.
4. **Never create Student Login.**
5. Students remain central data entities.
6. Teacher self-attendance requires browser location.
7. Teacher location currently allows **ANY LOCATION**; no geofencing.
8. Send latitude, longitude, accuracy and timestamp to backend.
9. Do not send teacher ID from frontend for self-attendance.
10. Use reusable components and centralized API services.
11. Do not create fake permanent functionality.
12. All frontend APIs must be structured for real backend integration.
13. Backend will independently enforce authentication and authorization.
14. The application must be responsive and production-quality.
15. No major console errors, warnings, broken routes or horizontal overflow.
